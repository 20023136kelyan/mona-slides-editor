# Gate 4 parity ledger

Status: **complete**. Gate 5 is unlocked.

Exit evidence: `npm run parity:gate4` passed all 46 shared Vue/React
contracts on 2026-07-20 after the final live-state interaction corrections. The
suite runs the same document, browser inputs, source-shaped state probes,
geometry probes, computed-style probes, history probes, and visual captures
against both applications. React-only journeys are retained as maintenance
coverage, but they are not used to award parity.

This ledger distinguishes four states:

1. `present` — React code exists;
2. `functional` — React works in isolation;
3. `parity verified` — the same automated Vue and React contract passes;
4. `approved` — visual evidence has been reviewed where the behavior is visual.

Only rows that are both `parity verified` and, when applicable, `approved` can
close Gate 4. `Pending` on either application is a failed gate, not deferred work.

## Audit rule

Every implementation change must identify its Vue source rows, add or extend the
Vue characterization contract first, run the equivalent React contract, compare
normalized document/session state, and attach screenshot evidence for visible
states. The row remains open if any source branch or element-specific variant is
untested.

Gate 4 does not claim the complete element toolbars/property panels or the
presentation-level workflows. Those are explicitly owned by Gates 5 and 6. In
particular, slideshow/search/print/import shortcuts and file-import branches are
not silently counted here; they must pass their workflow contracts before those
later gates can close.
