# Internationalization architecture

Migration note: this document describes the current Vue reference implementation. The React target keeps the same catalogs, locale contract, storage key, detection, lazy loading, and content boundaries, but replaces Vue I18n with typed i18next/react-i18next integration. See [REACT_MIGRATION_BLUEPRINT.md](./REACT_MIGRATION_BLUEPRINT.md#internationalization).

Mona Slides uses Vue I18n in Composition API mode. English (`en-US`) is the source locale and runtime fallback. Simplified Chinese (`zh-CN`) is the first secondary locale. French, Spanish, Italian, German, and Japanese are registered as planned locales but remain unavailable until their catalogs are complete and tested.

## Runtime behavior

Locale selection follows this order:

1. The user's saved choice in `localStorage` under `mona:ui-locale`.
2. The browser's ordered `navigator.languages` preferences.
3. English (`en-US`).

The selected locale is loaded before the Vue application mounts, preventing a flash of the wrong language. English is bundled with the initial application; secondary catalogs are lazy-loaded. Changing the locale updates Vue I18n, `<html lang>`, document direction, and the saved preference without reloading the page.

## What is translated

The locale catalogs own product interface copy: menus, tooltips, dialogs, validation, errors, accessibility labels, configuration-driven labels, starter element text, and generated default labels.

Presentation content is document data. Imported slide text, user-created text, speaker notes, and template artwork are never translated automatically. Native font family names also remain in their original script because changing them would break font matching.

## Files

- `src/i18n/index.ts`: Vue I18n instance, lazy loading, switching, persistence, and document metadata.
- `src/i18n/locales.ts`: supported and planned locale registry plus browser detection.
- `src/i18n/locales/en-US.json`: canonical message schema and fallback catalog.
- `src/i18n/locales/zh-CN.json`: secondary catalog with the exact same structure.
- `src/components/LocaleSwitcher.vue`: user-facing language control.
- `scripts/check-i18n.mjs`: catalog parity and untranslated-interface guard.

## Adding a language

1. Copy `en-US.json` and translate values without changing keys, interpolation names, object structure, or array length.
2. Add a lazy loader in `src/i18n/index.ts`.
3. Move the locale from `PLANNED_LOCALES` to `LOCALES` in `src/i18n/locales.ts`.
4. Add its language name to every supported catalog.
5. Run `npm run i18n:check`, `npm run type-check`, and `npm run build`.
6. Visually test the editor, dialogs, mobile layout, slideshow, overflow behavior, and fonts in that locale.

Use semantic, feature-scoped keys such as `export.pdf` or `animationPanel.duration`. Reuse genuinely identical terms from `common`; do not build sentences by concatenating translated fragments. Use named interpolation for variable content and preserve user data verbatim.

## Enforcement

`npm run i18n:check` verifies that English and Chinese have identical schemas, rejects Chinese text in the English catalog, and scans Vue templates and TypeScript string literals for untranslated Chinese UI. Native font names are the only allowlisted literals. Production builds run this check automatically.
